# Focusr

（旧名：Kugiri Timer。2026-10-12 に名前を変えました）

Android 向けの作業タイマーです。作業と休憩を区切ってくり返し、集中力を保てます。カレンダーと、コマをまとめたラウンド（時間割）で予定を管理でき、壁紙と BGM で落ち着いて作業できる画面にできます。

Release の `focusr-<版>.apk` から入れられます（下の「Android 版」）。ブラウザーで使える Web 版もあります（下の「Web 版」）。

Windows 版（Electron）は、2026-11 に配信をやめました。データは、Windows 版の「書き出し」で作ったファイルを、Android 版の「読み込み」で引き継げます。

2026 年 10 月に「Pomodoro Timer」から名前を変えました（「Pomodoro」は商標の持ち主のガイドラインで、許可なくアプリ名に使うことが認められていないため）。

## 機能

### タイマー

- 作業 → 短い休憩 → 作業 … を自動で切り替え、決まった回数ごとに長い休憩を入れる
- 作業・休憩が終わったとき、またはスキップしたときは、次のセッションが自動で始まる（止めるときは一時停止）
- スタート / 一時停止 / リセット / スキップ（Space キーでスタートと一時停止）
- 円形のプログレス表示と、モードごとの色分け。タイマーの下に今の時刻を小さく出す
- 作業・休憩の時間と、長い休憩までの回数を、iPhone のタイマーのようなホイールで設定（マウスホイール・矢印キー・クリックでも操作可能）。メイン画面の右上のタイマーのボタンから開く
- タイマーのプリセット：定番（25/5/15 分・4 回）・長め（50/10/30 分・2 回）から選べるほか、今の設定に名前を付けて 10 個まで保存できる
- 設定の変更はすぐに反映・保存される。始めたセッションの進み具合は消さず、新しい時間は次のセッションから使う
- ストップウォッチ：カードの左上のボタンでタイマーと切り替える。0 から数え上げ、数えた時間は集中の記録に足す（タイマーに戻しても動き続ける）

### レベルと称号

- 作業の時間 1 分ごとに 1xp。Lv0 から始まり、Lv0→1 は 100xp、そのあとは必要な xp が 50 ずつ増える（`src/level.js`）
- レベルに応じて 13 段階の称号が付く（`src/titles.js`）。カードの円の中に、Lv・称号・次のレベルまでの進みを出す

### カレンダーとラウンド

- カレンダー：右上のカレンダーのボタンで開く。月のカレンダーで日を選ぶと、その日の「予定」と「ラウンド」をタブで分けて見られる
- ラウンド：続けて行うコマ（授業など）のまとまり。毎週〇曜日か、その日だけ。ラウンドの下にコマが並び、ラウンドの名前の変更・コマの追加・編集・消す・この日だけ休むができる
- ラウンドのタイマー：ラウンドの最初のコマから最後のコマまで、タイマーが時計に合わせて自動で進む（コマは作業、コマとコマの間は休憩）。その間は、スタート・リセット・スキップ・タイマーの長さの変更は押せない（音楽と BGM は操作できる）。切り替わりでアラームを鳴らし、コマを終えるとそのコマの集中の回数が増える。作業の時間は集中の記録に数える（通常のタイマーと重なる時間は 1 回だけ）
- 画面の下の引き出し：予定のタブでは「予定を追加」で予定のフォーム、ラウンドのタブでは「ラウンドを追加」でラウンドを作るフォームとラウンドの道具（ほかの曜日にコピー・この曜日の毎週のラウンドを消す）、「カレンダーの設定」で予定の前の知らせと外部カレンダーを開く。一覧の予定・ラウンド・コマを押すと、引き出しで編集・削除できる。∨・Esc・Android の「戻る」・下へのスワイプで閉じる
- 予定のくり返し：この日だけ / 毎日 / 平日（月〜金） / 毎月〇日（毎週のものはラウンドで作る）。くり返す予定は終わりの日を決められ、「この日だけ休む」もできる
- ラウンドを作る：名前・この日だけか毎週か・開始時刻・1 コマの長さ・休み・長い休み（昼休みなど）・コマ数から、「1限」「2限」… のコマの入ったラウンドを作る。ほかの曜日にコピー、この日 / この曜日をすべて消すもできる
- 予定（カレンダーの予定とラウンドのコマ）の開始・終了時刻に通知する。カレンダーの予定の開始時刻には、タイマーが止まっていれば作業の頭に準備する（スタートは自分で押す。予定にプリセットを選んでいればその時間で）
- 予定の 1・3・5・10 分前に知らせることもできる（カレンダーの設定の引き出しで選ぶ）
- 外部カレンダー：Google カレンダーなどの「iCal 形式の非公開 URL」を 5 つまで登録して、予定を読み取り専用で取り込める（起動したとき・30 分ごと・「今すぐ更新」で読み直す）。取り込んだ予定も、自分の予定と同じく知らせ・タイマーの準備・次の予定・集中の記録に使う。終日の予定は一覧に出すだけ。URL は端末の中で暗号化して保存し、書き出しのファイルには入れない（Android 版だけ）
- メイン画面に、今やっている予定か次の予定（ラウンドのコマも含む）を 1 行出す（押すとカレンダーを開く）
- 予定ごとの集中の記録：作業を数えた分数と、最後まで終えた作業の回数を、その時刻の予定ごとに残す（3 か月分）。カレンダーの一覧で「集中 50 分・2 回」のように見られる
- 記録の画面：カレンダーの「記録」タブで、週（月曜始まり）・月ごとの集中の合計と回数、日ごとの棒グラフ（縦軸付き）、前の週・月との差を見られる。合計には、予定がない時間の作業も入る。一番下に、記録のしかた（何を・いつ数えるか）の説明がある
- 予定の通知：Android 版は先に Android に預けるので、アプリが裏にあっても出る（Web 版は、タブを開いている間だけ）

### 見た目

- 画面の大きさに合わせて、タイマー全体（文字も含む）が拡大・縮小する。幅を狭めてもボタンの文字は改行しない
- テーマの切り替え（Auto / Light / Dark。Auto は端末の設定に合わせる）
- 壁紙（デフォルト 5 種類：Dawn / Ocean / Forest / Night / Paper、画像の取り込みも可能）。壁紙があるときは、タイマー部分をすりガラスのカードにして読みやすくする。カードの不透明度は Appearance タブで 0〜100% に調整できる（100% で不透明、0% でぼかしも消えて完全に透明）。カードを薄くすると、文字のまわりにうっすら影が付き、壁紙の上でも読みやすくなる
- 起動モーション：起動したときに、タイマーの円が一周描かれてアプリ名が出る、約 1.2 秒の動き（「動きを減らす」設定のときは出さない）
- タイマーの数字のフォントを 6 種類から選べる（標準・細字・極太・角ばった字・等幅・明朝風。Windows のフォントに似たものを同梱している）

### 音

- BGM：取り込んだ曲（MP3 / WAV / OGG / M4A）と、ノイズ（White / Pink / Brown Noise。アプリの中で作る音で、音声ファイルは使わない）
- BGM を選んでいるときは、画面の下に再生バーが出る（YouTube Music と同じ並び：前へ・▶ / ⏸・次へと経過時間、ジャケットと曲名、音量・リピート（オフ / 全曲 / 1 曲）・シャッフル・▲。上の端に再生位置の線）
- 再生バーの ▲ や曲名のあたりを押すと「再生中の画面」が開く（左に大きなジャケットと曲名、右にキュー。上に残り時間とモードを小さく出す）。キューで曲を選ぶ・並べ替える（ドラッグか Alt + ↑ / ↓）・プレイリストを切り替える・ノイズに切り替えることができる
- ジャケットは、曲のファイルの中の絵（MP3 の ID3 タグ・M4A の covr）を読んで出す。絵がない曲は音符、ノイズは波の記号
- Android 版の再生バーは、ジャケット・曲名・▶ だけの細いバー。押すと全画面の再生中の画面が下から出て、大きな操作の並びと、一番下の「キュー」のつまみが出る。下へスワイプか「戻る」で閉じる
- 自分のプレイリストを 10 個まで作れる（「全曲」と切り替えて使う）
- 再生のルール：取り込んだ曲は ▶ / ⏸ を押したときだけ再生・停止する（休憩中も流れ続ける）。ノイズは ▶ / ⏸ に加えて、作業が始まると流れ、休憩になると止まる。起動したときはどちらも止まっている
- Android のロック画面・曲の通知と、キーボードのメディアキー（Media Session）で操作できる
- 音量は Alarm（終了時のチャイム）・BGM・SE（ボタンの操作音）の 3 つに分けて調整でき、それぞれ Test で試聴できる。Master の音量で、3 つをまとめて上げ下げできる（実際の音量は「Master × それぞれの音量」。耳で聞いた差が数字の差に合うように、2 乗した大きさで鳴らす）
- アラームの音は Chime / Bell / Digital / Marimba の 4 種類、SE（ボタンの操作音）は Pop / Click / Wood / Soft の 4 種類から選べる（選ぶとその場で試聴できる）
- Sound タブの「初期化」ボタンで、音量とアラーム・SE の音を初期値に戻せる（確認あり。BGM の選択はそのまま）

### そのほか

- 設定は画面全体に重なるパネルで、Sound / Appearance / General のタブに分かれている
- Esc・何もないところのクリック・右クリックで、メイン画面に向かって 1 つ戻る（設定パネル → 再生バーの小窓の順に閉じる）
- 多言語対応：Deutsch、English、Español、Français、Русский、සිංහල、简体中文、繁體中文、日本語、한국어 から General タブで選べる。初めて起動したときは端末の言語に合わせる（中国語は、地域が台湾・香港・マカオなら繁体字、それ以外は簡体字。対応していない言語は「English」）。日本語・英語・韓国語以外の訳は、話者による確認がまだ
- タイマーの終わりと予定の通知（Android の通知）
- 保存データの書き出し・読み込み（General タブ。1 つの JSON ファイルにまとめる。取り込んだ曲と壁紙のファイルは含まない）
- 一般タブにクレジット（作者・開発協力・Pomodoro Technique® の商標について）
- 更新のお知らせ（起動時に新しい版の APK を確認する。下の「Android 版」）

取り込める形式は、壁紙が PNG・JPEG・WebP・GIF、BGM が MP3・WAV・OGG・M4A です。取り込んだファイルはアプリの中（IndexedDB）にしまうので、元のファイルを移動・削除しても使い続けられます。アプリから削除しても、元のファイルは消えません。

## 必要なもの

- Node.js 22 以降（テストのスクリプトがファイル指定にグロブパターンを使うため。Capacitor 8 も Node 22 以上が必要）
- APK のビルドは GitHub Actions で行うので、手元に Android Studio は要らない

## 使い方

```bash
npm install
```

開発中の画面は、`src` をそのまま配ってブラウザーで開いて確かめます（ES モジュールを使うので、ファイルを直接開くのではなく、小さなサーバーを通します）。例：

```bash
npm run dev
```

表示された `http://127.0.0.1:5173/` を開きます（ポートは環境変数 `PORT` で変えられます）。データ（localStorage・IndexedDB）は `http://127.0.0.1:<ポート>` ごとに別になるので、`PORT` を変えると別のデータになります。

Android の開発版 APK は、下書き（draft）の Release「dev」の `focusr-dev.apk` から取れます（Releases のページ。下書きはリポジトリに書き込める人にしか見えません）。完成版と並べて入れられ（名前は「Focusr (開発版)」）、更新の知らせは出ません。

### テスト

タイマーや設定、更新のお知らせの状態遷移などのロジックを、Node.js 標準の `node:test` で検証します。あわせて、全ソースファイルの構文エラーも検査します。

```bash
npm test
```

GitHub に push すると、GitHub Actions（`.github/workflows/test.yml`）でも同じテストが自動で実行されます。

### リリース

`v` で始まるタグを push すると、GitHub Actions（`.github/workflows/release.yml`）が次の処理を自動で行います。

1. テストを実行する
2. タグと `package.json` の `version` が一致しているか確認する（ずれていたら止める）
3. `release-notes/<タグ>.md` から Release のタイトルと説明文を取り出す（ファイルがない・空なら止める）
4. GitHub Release を作る（タイトルと説明文が入る）
5. Android 版の APK を作り、その Release に `focusr-<版>.apk` として加える（`.github/workflows/android-build.yml`）

インストール済みの Android 版は、起動時に最新の Release を見て、新しい版の APK があれば更新を知らせます。

リリースの手順：

1. `package.json` の `version` を新しい番号に変える
2. `release-notes/v<番号>.md` を作る。1 行目に `# タイトル`、その後に説明文（Markdown）を書く
3. この 2 つをコミットして push する
4. タグを付けて push する

```bash
git tag -a v1.2.0 -m "v1.2.0"
```

```bash
git push origin v1.2.0
```

説明文のファイルは、手元でも次のコマンドで確認できます（タイトルが表示され、説明文が指定したファイルに書き出されます）。

```bash
node scripts/release-notes.mjs v1.2.0 release-body.md
```

更新のお知らせは、リポジトリが公開（Public）されている必要があります。非公開のままだと、アプリから Release を読めないため、更新の確認は失敗します（エラーは画面に出しません）。

### Web 版

URL：<https://marusako.github.io/focusr/>（main に push すると、`.github/workflows/pages.yml` がテストを通してから `src` をそのまま GitHub Pages に公開します）

Android 版と同じ画面を、ブラウザーでそのまま使えます。Android 版との違いは次のとおりです。

- **外部カレンダー**：使えません（カレンダーのサーバーが、ほかのサイトからの読み取りを許していないため）。カレンダーの設定に「Android 版だけで使えます」と出します
- **通知**：ブラウザーの通知です。設定の「通知」で許可が要ります。タブを開いている間だけ届き、閉じると届きません（`src/web-notice.js`）。ブロックされたときは、ブラウザーの設定から変えます。Android の Chrome では今は通知が出ません（ページから直接通知を作れず、Service Worker が要るため。PWA にする次の段階で対応する予定です）。iOS の Safari などブラウザーに通知の仕組みがないときは、通知の欄が出ません
- **データ**：そのブラウザーの中（localStorage・IndexedDB）にだけ残ります。ブラウザーのデータを消すと消えるので、「書き出し」でファイルにして持ち出せます。Android 版へも、「読み込み」で引き継げます
- ロック画面の表示や曲の通知など、Android の機能を使うものはありません

### Android 版

今の画面（`src`）を [Capacitor](https://capacitorjs.com/) で包んだ Android のアプリです。開発に使うパソコンに Android Studio を入れなくてもよいように、APK は GitHub Actions でビルドします。

- **ビルド**：main に push すると（画面や部品が変わったとき）、`.github/workflows/android.yml` が開発版の APK を作り、下書きの Release「dev」に置きます。手で動かすこともできます（Actions の画面の「Run workflow」）。リリースのときは、Release にも APK を加えます
- **`android/` フォルダー**：git には入れず、ビルドのたびに作り直します（`npx cap add android`）
- **署名**：GitHub の Secrets（`ANDROID_KEYSTORE_BASE64`・`ANDROID_KEYSTORE_PASSWORD`）に入れた固定の鍵で署名します。鍵が同じなので、新しい版を上書きでインストールでき、設定も引き継がれます。鍵をなくすと上書きの更新ができなくなるので、控えは開発者が保管します
- **版の番号**：versionName は `package.json` の `version`、versionCode は版から作ります（1.2.3 → 210203。版の番号を付け直したときに、前に入れたアプリの上から入れられるよう土台の数を足している。`src/mobile-update.js`）
- **通知**：タイマーが動き出したら、終わる時刻に Android の通知を予約します（`src/mobile-notice.js`）。正確な時刻に出すために、`USE_EXACT_ALARM`（Android 12 は `SCHEDULE_EXACT_ALARM`）の権限を付けています。最近使ったアプリの一覧からアプリを閉じると、端末によっては予約した通知も消えます
- **更新**：起動したときに GitHub の最新の Release を見て、新しい版の APK があれば知らせます。「更新する」を押すとブラウザーで Release のページを開くので、`focusr-<版>.apk` を押してダウンロードし、ダウンロードしたファイルを押して「インストール」を押します（Google Play 以外から入れたアプリは、Android の決まりで自動では入れ替えられません）
- **曲・壁紙の取り込み**：Android のファイル選択の画面で選び、アプリの中（IndexedDB）にしまいます（`src/web-media.js`）。アプリを更新しても残りますが、アンインストールすると消えます
- **データの書き出し・読み込み**：1 つの JSON ファイルです（`src/web-data.js`・`src/data-file.js`）。書き出しは Android の共有の画面で、ドライブや「ファイル」アプリなどに送ります。以前の Windows 版で書き出したファイルも読み込めます
- **外部カレンダー**：iCal 形式の非公開 URL で取り込めます。URL は、このアプリの小さな部品（`mobile/UrlVault.java`）が Android の Keystore の鍵で暗号化して保存し、書き出しのファイルには入れません。.ics は Capacitor の CapacitorHttp で読みます（画面の CSP はそのまま）。読み直すのは、開いたときと、アプリが動いている間の 30 分ごとです
- **作業中のアプリの制限**：設定の「一般」タブでオンにし、止めるアプリを選ぶと、作業のタイマー（通常のタイマーの「作業」とラウンドの作業のコマ）が動いている間、そのアプリを開くと「作業中」の画面（残り時間と「ホームに戻る」）が重なります。休憩中・一時停止中・止まっているときは開けます。ラウンドの作業のコマは時計どおりに進むので、一時停止では解除できません。設定で「制限する」をオフにすると解除できます。Android の設定で「使用状況へのアクセス」と「ほかのアプリの上に重ねて表示」の許可が要ります。ストア以外から入れたアプリなので、許可の切り替えが灰色で押せないことがあります（Android の「制限付き設定」）。そのときは、灰色の切り替えを一度押してから、アプリ情報 → 右上の︙ →「制限付き設定を許可」を押すと、許可できるようになります。作業の時間帯をフォアグラウンドサービスに渡すので、画面が裏にあっても動きます（`src/app-block.js`・`mobile/AppBlock.java`・`mobile/AppBlockService.java`。決めたことは `docs/plans/app-block.md`）
- **アイコン**：`mobile/res` の絵です。ビルドのときに、Capacitor の初めのアイコンと置きかえます

## 設計メモ

- **残り時間は終了予定時刻から計算する**：スタート時に終了予定時刻を決め、毎回「終了予定時刻 − 現在時刻」で残りを求めます。`setInterval` の呼び出しが遅れても、誤差が積み重なりません。
- **ロジックと画面の分離**：`src/timer.js` は状態を書き換えず、新しい状態を返す関数だけで構成しています。そのため、画面を開かなくてもテストできます。
- **セキュリティ**：Content Security Policy で、外部のスクリプトとスタイルの読み込みを禁止しています。外との通信は、Android 版が最新の Release を確かめる GitHub の API だけです。
- **取り込んだファイルの読み込み**：取り込んだ曲と壁紙は IndexedDB にしまい、`blob:` の URL で読みます。保存名はアプリが付けたランダムな名前（英数字とハイフン + 許可された拡張子）に限ります。
- **自動開始の基準時刻**：次のセッションは「前の終了予定時刻」ではなく「終了を検知した時刻」から数えます。スリープ明けなどで更新が遅れても、何回分もまとめて完了扱いになりません。
- **ホイールの値の確定**：マウスホイール・矢印キー・クリックでは行き先が分かっているので、スクロールの完了を待たずにすぐ確定します。指やマウスでつかんで動かしたときだけ、スクロールが止まった位置で確定します（それ以外のスクロールは見た目のためだけのもので、途中で止まっても値を決め直しません）。マウスホイールは 1 目盛りで 1 つずつ動かします。
- **保存先**：設定・予定・時間割・集中の記録・xp は `localStorage` に項目ごとの JSON で、取り込んだ壁紙・BGM は IndexedDB に保存します。
- **外部カレンダー**：Google の API とログイン（OAuth）は使わず、カレンダーの「iCal 形式の非公開 URL」から .ics を読みます。そのため、API の利用規約・開発者登録・審査が要りません。URL を知っている人は誰でも予定を読めるので、URL は Android の Keystore の鍵で暗号化して保存します。通信は Android 側（CapacitorHttp）で行い、画面の Content Security Policy（外との通信の禁止）はそのままです。.ics の読み取りには [ical.js](https://github.com/kewisch/ical.js)（MPL-2.0）を手を加えずに使っています（`src/vendor/` に写し、ライセンスの文章も同じ場所に置いています）。
- **「Focusr」への名前の変更**：画面・Android に出す名前を「Focusr」に変え（2026-10-12）、そのあと中の名前（`package.json` の `name`、Release のファイル名 `focusr-<版>.apk`、書き出すファイルの `app` と名前、同梱したフォントの名前、Android のアイコンの部品の名前）も「Focusr」にしました（2026-10-15）。2026-11-03 に残りもそろえました：GitHub のリポジトリ名（`focusr`。Web 版の URL も `/focusr/` に変わりました）、Android 版のアプリの識別子（`io.github.marusako.focusr`）、保存場所の名前（`focusr-media`・`focusrFeeds`・鍵の名前 `focusr-feed-url`）。識別子が変わったので、0.2.0 からの Android 版は以前のアプリとは別のアプリとして入ります（以前のアプリの上からは更新できません）。データは、以前のアプリの「書き出し」で保存したファイルを、新しいアプリの「読み込み」で戻してください。以前の名前（`app: 'kugiri-timer'`）で書き出したファイルも読み込めます。署名の鍵の中の名前だけは、鍵を作り直さないと変えられないので、以前のままです。
- **版の番号の付け直し（2026-11-03）**：Release を 2 つだけ残して付け直しました（最初のリリース 1.0.0 → `v0.0.0`、Android 版の試作版 2.0.0 → `v0.1.0`）。ほかの Release とタグ（1.1.0〜2.9.1）は消しました。次の版は 0.2.0 です。2.9.x を入れた Android 版は、新しい 0.x を「新しい版」と判断しないので更新を知らせません。次の版は Release のページから手で入れてください（versionCode の土台を上げたので、上から入れられ、データも残ります）。
- **音の生成**：Alarm・SE・ノイズは Web Audio API でその場で作るため、音声ファイルを同梱していません。アラームと SE の音は「楽譜のデータ」（`src/alarms.js`・`src/se-sounds.js`）と「鳴らす処理」（`src/sound.js`）に分けているので、音の長さや重なったときの大きさを、音を鳴らさずにテストできます。
- **画面サイズに合わせた拡大**：メイン画面の大きさは、CSS の変数 `--u`（標準のウィンドウでの 1px が、今の画面で何 px になるか）を掛けて決めています。`--u` は「幅 ÷ 410」と「高さ ÷ 600」の小さいほうなので、縦長でも横長でも画面からはみ出しません。基準の幅 410 は、いちばん幅を取るボタンの並び（韓国語の「일시정지」表示時）が、幅 320px（小さめのスマホ）まで 1 行に収まるように決めています。JavaScript を使わず CSS だけで計算するため、ウィンドウの大きさを変えるとすぐに反映されます。
